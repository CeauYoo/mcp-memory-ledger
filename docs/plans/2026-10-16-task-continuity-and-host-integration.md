## 一 结论与产品目标

建议保持 Rust + SQLite + MCP 的本地记忆核心，新增一个有界、可替换的客户端协作接入层。下一阶段的主要成果应是：**原始要求不会被后续补充覆盖，任务中断后可以准确续接，已有经验在适当时机进入上下文，关键动作按真实执行边界检查，交付结果能够反过来纠正经验。**

这不是承诺模型永远理解正确，也不是把项目重写成通用自主 Agent 平台。它把现在已有的记录、检索、纠错和经验版本能力，接到真实工作过程中。

产品目标：少重复解释，少提醒一次已经说过的要求，少重复同类错误；该自主处理的步骤不中断，该由用户决定的节点能够准确停下。

## 三 研究如何影响本规划

研究范围为截至 2026-10-16 可核验的原始论文、作者资料和官方技术文档。优先阅读与项目缺口直接相关的机制、实验设置和局限；论文中的榜单成绩不等于本项目的实测收益。可变官方文档采用本次访问日期，不伪造发布日期或用户本机能力。

### 1 从记忆保存推进到实际使用

MemoryArena（2026-02-18，v2 2026-09-17）把记忆与跨会话行动联动评估；其结果提醒我们，长对话问答表现不能直接代表任务执行表现。规划吸收其多会话相互依赖任务设计，不照搬整套评测平台。[原文](https://arxiv.org/abs/2602.16313)

LongMemEval-V2（2026-05-12，论文注明 Work in Progress）关注环境状态、工作流、常见陷阱及问题前提。它支持把证据组织成可用上下文，但不是无人监督执行的证明。[原文](https://arxiv.org/abs/2605.12493)

### 2 经验需要选择和撤回

PATH-Bench（2026-08-02）研究经验顺序及干扰，发现积累经验并不总能改善任务表现。规划据此加入“不适用”和“拒绝采用”状态，并保留无经验回退路径。[原文](https://arxiv.org/abs/2608.01149)

MemCalib（2026-09-21，v3 2026-10-08）区分记忆过度使用与使用不足。其训练方法需要模型训练条件；本项目吸收的是适用性与采用效果的双向检查，不在本轮引入强化学习。[原文](https://arxiv.org/abs/2609.24259)

Reliable Memory / RBC（2026-10-13）通过随机纳入或移除经验块估计效果。研究限于其模型、任务和固定经验集，且增加实验成本。规划保留离线对照能力；生产任务不随机移除用户硬约束，也不把一次成功归功于某条经验。[原文](https://arxiv.org/abs/2610.18427)

### 3 计划与事实必须分开

AgentMemGate（2026-10-06）指出未落实计划可能被错误写成当前事实，提出暂存及条件晋升。实验采用有限字段和构造对话，不能泛化为零错误保证。项目将计划、要求、观察与结果分开表示：批准方案不等于已经执行，计划部署不等于已经部署。[原文](https://arxiv.org/abs/2610.07707)

上述研究支持设计方向；后续接口、状态机和实施次序是结合本项目提出的工程方案，不是论文已替本项目验证的结论。

## 四 架构与信任边界

### 记忆核心

继续负责持久化、范围隔离、来源追溯、任务与经验版本、上下文选择及结果记录。不连接任意外部系统替用户执行任务，不把模型产出的规则自动升级成权限。

### 客户端协作接入层

负责绑定 `workspace_id + task_id + host_session_id`，在宿主支持的生命周期事件中请求任务上下文，转换成宿主可接受的输入，并记录送达结果。宿主没有某项能力时应明确降级；普通 MCP 模式仍可用，但不能显示为“自动接入已启用”。

### 实际执行层

执行前检查只能在动作真正经过的入口生效。操作系统沙箱、宿主原生权限系统及受控工具优先。hooks 可以补充检查，不能宣称拦截所有路径。自由 shell 的语义和子进程效果不能靠字符串黑名单可靠判断。

### 三类记录不能混为一谈

1. **任务要求**：用户当前要求做什么、不能做什么、以什么为完成标准。
2. **经验与事实**：过去发生过什么、哪些做法可能适用，有什么证据和局限。
3. **执行授权**：可信入口确认的具体操作范围、对象与有效期；不能由普通记忆写入接口自行制造。

可信入口尚未建立时，只能记录“调用方报告已批准”，不能输出“已验证授权”。授权签发、撤销与普通模型可调用的记忆写入必须分开；模型能写一个 approval 字段不代表得到权限。同一操作系统用户可修改配置或数据库的现有威胁边界也必须保留。

## 五 分阶段任务规划

优先次序：P0 → P1 → P2 → P3；P4 在 P2 的接口稳定后可并行。安全与可恢复性贯穿各阶段；验证随功能交付，不单独扩张为大型测试平台。

### P0 校正基线并固定宿主能力合同

这是首批功能变更的前置工作，不另开文档冲刺。

- 对照已完成提交校正唯一 active plan、状态页和 Windows/历史接入旧描述。
- 增加宿主能力清单：启动注入、续接注入、压缩后注入、操作前检查、结果事件、失败行为、未覆盖工具。
- 将官方文档支持、已通过适配测试、用户本机已验证三种证据分开。
- 固定首个目标为 Codex 接入，Claude Code 使用相同协议做第二适配器。

完成条件：不存在“当前仍未支持 Windows”这样的错误待办；功能能识别宿主能力不足并给出简短状态；没有凭文档自动改动用户配置。

### P1 持久任务要求和可靠续接

**用户收益：后续补充不再盖掉最初要求，中断后不需要重新解释。**

工作包：
- T01 定义工作空间内任务、不可变修订、当前版本指针和生命周期状态。
- T02 为目标、要求、禁区、完成标准、待决问题提供稳定条目 ID；每次变更保留来源、替代关系、原因和 `expected_version`。
- T03 将模型提取的变更保留为候选；明确要求可由可信用户事件导入。补充条目不能隐式删除旧条目；冲突需要明确替代或标记待决。
- T04 保存 checkpoint：已完成步骤与证据、进行中步骤、阻塞项、建议下一步，以及环境/仓库版本和产物标识。恢复时检查产物是否仍存在且匹配，不能把旧完成标记直接当成现在仍有效。区分“计划”“已尝试”“结果已观察”“已验证”。
- T05 新增任务上下文接口，以任务 ID 直接装入有效要求，再选择关联记忆与经验。原 `build_task_context(query)` 保持兼容。任务硬约束使用独立必载区；空间不足时明确返回不完整并缩小任务范围，不可静默丢弃约束后继续声称上下文齐全。任务版本、checkpoint 和经验若不在同一读取快照，返回各自实际版本及 stale 诊断，不能把 context_id 当一致快照证明。

建议最小模型：`Task`、`TaskRevision`、`TaskRequirement`、`TaskCheckpoint`。已有 Claim 的 `Observed / Said / Acted / Inferred / Draft` 与验证结果 `Passed / Failed / Inconclusive / NotPerformed` 应尽量复用，不再造一套同义认识状态。持久写复用现有幂等回执和事务模式。任务生命周期与认识状态是不同轴，不能用一个 `active` 字段同时表达“获批”“真实”“有效”。

建议操作面：创建、修订、读取、列出、记录 checkpoint、构建任务上下文。最终 MCP 名称在实现设计时冻结，优先复用共享服务函数，不堆叠近义工具。

完成条件：多轮补充后所有未撤回要求仍在；陈旧版本写入被拒绝；新会话能恢复当前任务；含糊计划不会变成已发生事实；暂停/取消后不能继续被视为可执行任务。

### P2 Codex 接入与有边界的操作检查

**用户收益：无需反复提醒 AI 去读记忆，关键约束更早生效。**

工作包：
- T06 实现独立宿主适配协议和 Codex 插件/本地桥接；先使用当前公开生命周期接口，不依赖私有聊天记录格式。
- T07 启动、续接、压缩恢复及必要的任务版本变更时获取最新上下文；按版本缓存，不在每个无关工具调用前重放所有历史。
- T08 保存 context receipt，区分“核心已构建”“适配器已送达”“模型报告采用”“结果证实生效”。送达不能自动算作已理解。仅桥接命令成功输出时标记“已输出，宿主接收未验证”；只有宿主接受/注入证据才能记作送达。
- T09 为能明确约束的动作增加确定性检查：工作空间、任务状态、目标路径、授权引用、版本是否仍有效。检查结果可为允许、拒绝、需要确认、不支持；不支持不能映射为允许。
- T10 针对失效与覆盖缺口设计恢复：核心不可用、超时、版本变化、撤销授权、重复事件、旧会话、交互式命令及未覆盖工具。默认不扩大原宿主权限。对所选版本逐项映射返回值；没有 ask 能力时拒绝当前动作并请求确认，不能发送不支持的字段。故障下无法可靠阻断的路径仅标为提示性检查；必须硬阻断的操作需原生权限/沙箱或受控入口，否则不得启用此保护承诺。
- T11 配置生成仅做预览；支持备份、差异查看和撤回。实际安装到用户 Mac/Windows 另行确认。

任务要求、权限记录在动作前读取新版本；已结束动作不能被事后撤销。调用超时且结果未确认时记录 unknown，先核对真实结果，再决定重试；幂等回执只保证本系统写入，不能自动保证外部工具没有重复副作用。对可控执行器使用短生命周期、绑定任务版本及动作参数摘要的检查凭据；它不能替代宿主权限，也不能对外承诺普通模型调用无法绕过。

路径检查必须考虑真实路径、符号链接/重解析点、挂载和网络映射；“不是 Documents”不等于不在同步目录。对不受控 shell 或工具路径，不以成功检查一次路径保证全部后续副作用安全。

完成条件：在云端或隔离环境的固定版本真实宿主中，证明新会话和续接确实注入任务要求；不能以适配器单测替代这一证据；缺失 hooks 的宿主显示手动模式；明确覆盖的禁止动作被拦截；超时/绕行路径不被写成已受保护；无需更改模型 API 协议即可使用记忆。

### P3 经验采用与结果反馈

**用户收益：已纠正过的问题，更有机会在相似任务中被主动避免。**

工作包：
- T12 联合选择有效任务要求、当前事实、相关 Episode 和 active experience；给出适用条件、反例、来源与未采用原因。
- T13 新增 `ExperienceUse`：任务版本、经验精确版本、建议/采用/拒绝、关联动作、结果引用、评估方式及局限。
- T14 将用户纠正和工具结果写回已有 Episode/反馈流程，复用经验修订与回滚；不新造第二套经验仓库。
- T15 对过时、污染或被证伪的经验停止后续召回，清除受影响的派生缓存，标记受影响任务；保留原始来源和历史。
- T16 支持有证据的候选归纳。自动提炼只生成候选，不自动获得全局效力、执行能力或新权限。

完成条件：可以回答“此次用了哪条经验的哪个版本、是否符合适用条件、结果证据是什么”；纠正后下一相似任务不会继续收到旧 active head；无证据时显示未知；相似但不适用的经验不会强制采用。

先记录描述性结果，不把相关性当因果效益。经验的收益排序进入后续有对照的迭代，不能仅凭模型打分决定“越用越聪明”。

### P4 检索质量和时效语义

**用户收益：换一种说法也能找到相关经验，同时不被旧信息误导。**

工作包：
- T17 增加中文词法/别名与可解释查询扩展，保留原 query 和各路命中信息。
- T18 增加可选本地 embedding 索引和混合排序；FTS 与直接 ID 路径保留，向量索引可重建、可关闭，不能成为唯一真相源。候选可采用倒数排名融合（RRF）后做有界重排；是否增加复杂图检索由实际漏召回证据决定。
- T19 在候选生成与结果读取两个阶段维持工作空间限制；缓存按范围和索引版本隔离，禁止先全局召回再把截断结果当隔离正确。
- T20 增加明确的适用条件、版本/环境约束及有效区间合同；未知时间保持未知，过期事实与被纠正事实分别处理。

硬性任务要求通过 ID/任务版本直接载入，不依赖 embedding 相似度。默认不把私人记忆发送给第三方嵌入服务；如选择远程服务，需要明确数据范围、提供方与授权。迁移不偷偷为旧历史补造有效时间。

完成条件：保留既有精确召回正确性；选定中文改写和跨轮指代样本能改善；无相关证据时如实返回不足；向量路径失效能回退；跨项目命中为零是约束用例的验收要求，不是对所有未知攻击的安全证明。

### P5 简洁产品接入与日常可用性

此阶段随 P1–P4 的接口逐步交付，不重设计整套 UI。

- T21 原网页增加任务当前要求、进度、正在采用的经验及结果来源；清晰区分计划、运行、完成和待确认。
- T22 保留原版视觉、角色横幅、导航密度，统一中英日文键值；长译文、窄窗口、空态和错误态检查布局。
- T23 维持单核心全局接入、按工作空间和任务区分；多个未完成任务时提供简短选择，不能仅凭 cwd 猜唯一任务。
- T24 交付一套本地部署/撤回预览。配置、依赖、数据库、日志和构建产物均位于经确认的非同步目录；部署路径按目标平台逐项核验。

完成条件：状态来自真实事件、按钮有实际行为；普通使用不要求用户填写十几个运行参数；没有把未部署的新版本展示成已在用户机器运行。

## 六 实现约束与维护方式

- 纯领域函数处理要求合并、版本检查、经验适用性与上下文排序；I/O 留在存储和宿主适配边界。
- 建议模块边界：`domain/task`、`application/task`、`application/context_selection`、`application/experience_use`、`ports/host_session`、`adapters/codex`、`adapters/claude_code`。具体命名服从当前代码结构，不新建万能 manager。
- SQLite 使用显式 schema migration；修改任务和写回 receipt 原子完成。先按工作包确定最小 schema，不让一张无限增长 JSON 表承担所有关系。
- 复用现有备份恢复、范围策略和回执；新增 schema 需同步 doctor、迁移、备份、export、旧历史接入的保守拒绝条件。
- 任务信息只供已授权范围读取；个人偏好跨工作空间复用必须有明确规则，不能默认为全局可见。
- 检索文档、仓库文件、第三方消息及模型推测不能被自动提升为用户要求或授权。来源标签本身不构成生产者认证。
- 可撤回的是派生状态、经验当前版本和适配配置；已执行外部副作用必须单独判断是否有补偿动作，数据库回滚不等于现实世界回滚。
- 新增日志遵循最小必要原则，不记录密钥；模型请求/返回的诊断保存应可配置并脱敏，不默认全量收集所有用户会话。

## 七 验收围绕正常用户体验

验证跟随每个工作包，不以先建设大型评测平台阻塞功能。

建立至少 30 个独立多轮任务场景，六类各五例：
1. 初始需求与后续补充整合。
2. 暂停、重启、压缩后续接。
3. 同一错误被纠正后再次遇到相似任务。
4. 历史经验与新要求冲突、旧环境方法失效。
5. 工作空间隔离、约束与授权范围变化。
6. 计划未落实、含糊指代、无证据与来源污染。

场景包含多会话、长上下文、改写及干扰；至少部分历史达到一万 token 量级，报告实际长度和生成方式，不能把 30 个变体说成 30 个独立真实用户。生产中的硬约束不参加随机删减试验。

关注指标：未撤回要求覆盖率、重复解释/纠错次数、带证据的任务完成率、错误经验采用率、应确认和不必确认节点的准确性、重启后的恢复正确性，以及时延、实际 token 和已知价格下的成本。

对照条件应固定模型版本、任务输入和工具环境，比较无记忆、现有记忆工具、新任务接入方案。小样本结果只作为下一步产品决策，不宣传统计显著或通用模型提升。需要重复运行或更多样本时，根据观察到的方差决定。

质量底线：既有功能与三平台回归不退步；受支持执行路径的禁止动作不执行；没有证据不能报完成；敏感内容不因跨项目召回泄露。用户体验提升以实测差异报告，不预先承诺提升百分比。

真实模型体验保留足够输出空间，支持长任务自然完成；必要的防失控配额与花费透明显示且可配置，不能用极短输出或低到无法完成任务的额度制造“通过”。付费调用、用户机器验证和正式部署需另行明确批准，不由本实施计划自动授权。

## 八 首个可交付切片与范围

已批准实施，第一批直接完成 **T01–T08** 的最小闭环：创建任务 → 分轮补充且保留原要求 → 保存 checkpoint → 新会话接入 → 获得当前要求和下一步 → 查看上下文送达证据。P0 的事实校正并入这一批，并在原界面加入最小只读任务摘要，让首批具备可见可用的入口。

T09–T11 的受支持动作检查紧接其后；在完成前不宣称自主操作安全边界已建立。T12–T16 再让经验真正反馈到任务。P4 可在任务上下文合同稳定后并行，不能用引入向量数据库代替解决前面的缺口。

每阶段更新包含：新增功能、实际使用方法、验证结果、仍有限制、对应提交及可撤回方式。代码先在云端完成，经用户确认后才操作本地 Mac。推送继续限于既定开发分支与上游草稿 PR；不得据规划自动合并或发布。

本轮不优先：模型 RL/微调、无人监督自我改写权限、自动执行经验步骤、远程团队多租户、新图数据库迁移、全面 UI 改版、庞大发布证据平台。它们需要独立需求和收益依据。

## 九 补充研究与明确取舍

以下条目作为具体设计依据；本轮未运行作者代码或独立复现论文分数。

| 原始研究与日期 | 值得吸收的机制 | 本项目取舍与证据边界 |
|---|---|---|
| [Reflexion](https://arxiv.org/abs/2303.11366)，2023-03-20 | 反馈驱动反思，下一次尝试读取经验 | 反思必须关联真实结果；论文重试任务的收益不等于长期自主学习 |
| [MemGPT](https://arxiv.org/abs/2310.08560)，2023-10-12 | 运行时管理工作上下文与外部记忆 | 借鉴分层上下文；单独增加 MCP 工具不会自动获得其控制流 |
| [Zep](https://arxiv.org/abs/2501.13956)，2025-01-20 | 记录时间与事实有效时间分开，多路召回 | 在 SQLite 增量实现，不据旧论文推断 Graphiti 当前规格 |
| [A-MEM](https://arxiv.org/abs/2502.12110)，2025-02-17，阅读 v11 | 原子记忆、语义描述、关联扩展 | 原证据不可被生成摘要替代；仅有界扩展，图结构不是正确性保证 |
| [Mem0](https://arxiv.org/abs/2504.19413)，2025-04-28 | 候选抽取、比对、增量更新与 NOOP | 复用候选工作流；不照搬破坏式删除。对话 QA 不证明工程任务改善 |
| [ACE](https://arxiv.org/abs/2510.04618)，2025-10-06 | 带 ID 的经验条目、局部变更与整理 | 经验变更保留版本；helpful 自评不视为因果效果 |
| [Hindsight](https://arxiv.org/abs/2512.12818)，2025-12-14；[ACL 演示论文](https://aclanthology.org/2026.acl-demo.27/)，2026-07 | 区分事实、推断与经验，混合检索 | 复用当前 Claim 类型；预算与排序可借鉴，整套系统分数不能分摊给单个组件 |
| [AgeMem](https://arxiv.org/abs/2601.01885)，2026-01-05，阅读 v3 | 统一长短期记忆动作并训练策略 | 只借鉴少而清晰的接口；训练链留待未来，不认为有工具就自然学会 |
| [LifeMem](https://arxiv.org/abs/2609.12655)，2026-09-11 | 按工作流聚类，实例与抽象技能分层 | 有足够轨迹后再做；跨项目共享不等于可复制本地命令与权限 |
| [MemSecBench](https://arxiv.org/abs/2607.27080)，2026-07-29 | 跟踪持久化、执行后果和选择性修复 | 原条目撤回后检查摘要、索引与缓存；其完整配置比较不证明某数据库普遍更安全 |
| [AgentSpec](https://arxiv.org/abs/2503.18666)，2025-03-24，阅读 v3 | 将触发条件、谓词与处理动作外置 | 用于覆盖明确的运行时检查；不能据离散检查点推断任意未来副作用 |
| [ProbGuard](https://arxiv.org/abs/2508.00500)，2025-08-01，v4 2026-08-03 | 从轨迹估计后续风险 | 后续预警研究，不替代授权。状态抽象及训练分布限制其保证 |

原文之间使用的模型、数据、预算、评分器与宿主不同，不在此做横向排行榜。十月的新工作优先作为问题定义和机制参考，不因发表较新就认定可靠性已成熟。

## 十 官方工程资料与宿主兼容策略

### Codex

[官方 hooks 文档](https://developers.openai.com/codex/hooks/)在本次访问时支持启动/恢复/压缩等上下文接点，以及部分本地工具的执行前检查。但 hosted tools、后续交互输入等存在覆盖缺口；部分错误会放行。故本项目只对经过探针验证的事件和工具声明支持，不能把它写成完整执行安全边界。未核验用户已安装版本具备全部能力。

实现优先考虑稳定的本地命令桥接与明确拒绝结果，处理 MCP 尚未就绪的启动时序。不依赖模型主动调用记忆工具，也不自动弱化原生权限。具体协议必须按选定宿主版本实现，不能跨客户端直接复用相似字段。

### Claude Code

[官方 hooks 参考](https://code.claude.com/docs/en/hooks)提供相应生命周期和操作前控制；文档中 `onFailure:block` 要求 v2.1.295 或更高。默认故障行为与宿主配置有关，需要版本固定及实际故障验证。作为第二适配器共用领域协议，不把这项能力视为当前用户机器已经安装或启用。

### 长任务协作工程

- [Anthropic Context Engineering](https://www.anthropic.com/engineering/effective-context-engineering-for-ai-agents)，2025-09-29：借鉴高信号工作集与按需取证，避免将全部历史重复灌入上下文。
- [Effective Harnesses for Long-running Agents](https://www.anthropic.com/engineering/effective-harnesses-for-long-running-agents)，2025-11-26：借鉴功能清单、增量交付和可续接状态；模型自己打勾不是独立验证。
- [Harness Design for Long-running Apps](https://www.anthropic.com/engineering/harness-design-long-running-apps)，2026-03-24：借鉴实施前明确范围和验收方式；Agent 之间达成一致不能代替用户授权，不默认每个任务都启动多个角色。
- [Managed Agents 工程说明](https://www.anthropic.com/engineering/managed-agents)，2026-04-08：借鉴持久事件、执行器与当前模型上下文分离；不迁移到托管服务，也不据此承诺现有 MCP 已有同等恢复能力。
- [LangGraph Persistence](https://docs.langchain.com/oss/python/langgraph/persistence)与[Interrupts](https://docs.langchain.com/oss/python/langgraph/interrupts)，访问于 2026-10-16：借鉴持久待确认与恢复；恢复可能重跑节点，因此外部动作须幂等或核对实际结果，不需要把 Rust 改成 Python。
- [MCP 架构规范](https://modelcontextprotocol.io/specification/2025-11-25/architecture)，2025-11-25：宿主管上下文和权限，服务提供能力。MCP server 的范围检查不能替代宿主其他工具的策略。

宿主状态建议使用四个简短标签：**手动调用、自动送达、部分动作检查、受控执行器**。最后一项需要所有相关副作用入口都受控，当前只作为未来架构选项，不属于第一批交付。hooks 失效时，只暂停其承诺保护的动作并报告覆盖缺口；不把普通问答和无风险读取一并锁死，也不悄悄扩大可执行权限。
