# Enhanced recall and task continuation (partial MVP)

`recall_memory` retains its literal whitespace-separated substring contract. The separate `recall_memory_enhanced` operation retains the original query and exposes deterministic Jieba 0.11.0 tokens, exact-namespace single-hop host-configured aliases, per-route ranks, RRF score and omission counts. Query tokens and expanded terms are bounded. Aliases expand original tokens only; alias chains and other namespaces are never followed.

Candidate generation uses independently scoped authoritative exact scans, not a truncated global index result. The optional embedding path additionally reads a bounded authoritative scope window (up to 64 records) independent of lexical matches, so semantic-only candidates can be retrieved. This is a bounded window, not exhaustive semantic top-k. Candidate-window exhaustion is explicit. Current candidates are hydrated with scope and active-claim checks, full-content digests, and declared applicability checks before embedding and again before selection. Recording time is not inferred validity time. Positive cosine similarity only supplies ranking evidence, never factual verification, relevance certainty or execution authority.

Each SQLite enhanced record is preflighted inside one read transaction before its text and complete provenance are materialized: storage types, field byte lengths, edge counts and total raw bytes. Input guards are 32 KiB aggregate raw selected strings plus conservative field/row overhead per record, at most 128 rows per provenance relation, and 256 KiB aggregate source-scan preflight bytes. Lexical identifiers are capped at 256 bytes before materialization; oversized scoped identifiers are counted in warnings. The retained candidate union has a separate 1 MiB serialized allocation budget. Oversized records are omitted whole; candidate unavailability includes records that could not be safely materialized. Corrupt authoritative data returns an explicit error. Ranking covers all bounded, hydrated candidates before the result limit and whole-record JSON-byte packing. Oversized result records are skipped and later smaller records backfill. The serialized byte count includes metadata and counts, not a token estimate or transport envelope.

The optional local Ollama adapter uses real vectors, exact model tag/digest/dimensions and prefix settings, a literal loopback endpoint, no proxy, no redirects, no chat API key, an exact namespace allowlist and an operator local-only declaration. Embedding failure or invalid vectors retain lexical results; scan-only candidates are removed when no valid embedding rank exists. The enhanced operation gives its document-plus-query embedding sequence one five-second deadline. Task context can impose a shorter total optional deadline. See [local embeddings](local-embeddings.md) for the transport boundary and synthetic-only evidence.

## Schema 10 authority

Explicit migration adds `recall_applicability`, an authoritative revision history separate from rebuildable retrieval data. Reads and current-schema open do not install or silently recreate it. Existing records keep unknown validity; migration invents no timestamps. The explicit `SqliteStore::declare_recall_applicability` API accepts a caller declaration bound to namespace, canonical Claim/Event reference and full content digest, with compare-and-set revision and idempotent request ID. It does not run automatically from host context or model output. The explicit CLI is `retrieval declare --json '<request>'`; no implicit host write is performed.

Declarations include optional RFC3339 `valid_from` (inclusive), `valid_until` (exclusive), conditions and environment strings. Conditions are reported as declared and unevaluated, not assumed satisfied. Expired and not-yet-valid matching declarations exclude candidates; metadata for a different content digest is explicitly unknown. Authoritative JSON normal and replay reads validate type, individual and aggregate byte budgets in the same transaction before materialization, then validate JSON and relational agreement. Malformed authority is an explicit corruption error, never a reason to ignore declared restrictions.

Scoped export and namespace adoption reject relevant namespaces containing new applicability authority until an interchange closure contract exists. Other namespaces remain eligible under their existing rules. Full database backup is the preservation path.

## Task continuation

Host configuration selects `retrieval.task_context_mode = "literal"` (default), `"enhanced"` or `"hybrid"`; MCP requests cannot override it. `optional_deadline_ms` defaults to 2000 and accepts 100–5000. The shared service loads mandatory requirements directly by task ID/version before optional recall. One optional deadline covers experience-use history, memory recall, experience selection, revalidation and final version checking. Timeout retains mandatory requirements and reports missing optional work; if the final version cannot be checked, the result does not permit resumption without rechecking. Ordinary byte-budget protections still apply, including explicit incomplete output when mandatory requirements cannot fit.

## Remaining boundaries

- Optional derived vectors are cached only when host-enabled; explicit rebuild resets the derived cache for regeneration, with generation checks preventing old in-flight writes after reset. It is not ANN indexing or exhaustive semantic top-k. See [cache boundaries](local-embeddings.md#derived-vector-cache).
- Enhanced recall currently ranks Claim/Event records. Task requirements and active experience selection use their existing shared task service paths; the enhanced lexical ranking does not yet replace experience recall.
- Applicability condition/environment evaluation is not implemented. Unknown is preserved.
- Local model identity checks detect ordinary digest drift, not a malicious service or proof of local-only execution. No real model, user desktop or credential was used in these tests.
- Bounded tests establish the implemented fixtures, not universal isolation or production readiness.

Verification: `cargo test --test enhanced_recall --test task_ledger --test experience_use_feedback --test sqlite_lifecycle --test schema6_migration --test schema7_migration`; optional transport checks: `cargo test --test local_embedding`. Run Cargo serially in constrained cloud workspaces.
