# Optional local embeddings (partial MVP)

The modular `ports::embedding::EmbeddingPort` and `adapters::local_embedding::OllamaEmbeddingAdapter` use Ollama's actual `/api/embed` vectors. They do not hash text into pretend embeddings. Enhanced recall uses these vectors to rank lexical candidates plus an independent, bounded, already scoped authoritative source window. This supports semantic-only matches within that window; it is not exhaustive vector search, a persistent ANN index, or live model certification. Window exhaustion and allocation omissions are reported; see [enhanced recall](enhanced-recall.md).

Embeddings are disabled by default. Enabling requires `local_only_declared = true`, a nonempty exact namespace allowlist, and an explicit profile with the exact installed model tag, its SHA-256 digest, dimensions, and query/document prefixes. Configure prefixes for that model; changing any profile field means old vectors cannot be reused. Optional `cache_enabled = true` wraps the adapter with a disposable SQLite vector cache. It is disabled by default and installed/reset only by an explicit rebuild, never by a read.

Only literal loopback HTTP(S) origins are accepted; DNS names, URL credentials, paths, query strings and fragments are rejected. The independent HTTP client disables proxies and redirects, uses no chat-provider credentials, and has no remote fallback. **Loopback does not prove that the local service never forwards to cloud.** Operators must verify the service and model run locally before declaring this.

`/api/tags` must match the pinned digest before and after every embedding call. This detects ordinary tag drift, not a malicious server or an atomic model identity guarantee. The returned model and vector count/dimensions are checked, and non-finite/zero vectors rejected. Maximums: 64 texts, 256 KiB combined text plus prefixes, 8192 dimensions, 4 MiB response per request, and configured total deadline at most 60 seconds. The deadline begins before serialization, spans model checks and embedding response, and is checked after synchronous bounded work. Each HTTP response is bounded while reading. Errors omit service response bodies and submitted texts.

The synthetic loopback integration tests (`cargo test --test local_embedding`) never start or contact a real model or use credentials. Live model behavior and actual local-only operation remain operator verification requirements.

## Derived vector cache

CLI `agent_llm_mm retrieval cache-rebuild` (library `SqliteStore::rebuild_embedding_cache()`) explicitly installs/resets derived tables; vectors regenerate on subsequent authorized embedding requests. CLI `agent_llm_mm retrieval cache-clear` (library `clear_embedding_cache()`) clears existing derived rows. Neither operation changes authoritative memory or applicability declarations. Rebuild/clear rotates a generation marker so an inference started before reset cannot repopulate the reset generation.

Keys contain exact namespace, full-profile SHA-256 (model, digest, dimensions and both prefixes), purpose and input content digest. No raw texts are stored. Reads preflight type, dimension, byte length and aggregate size for all requested vectors in the same read transaction before materializing them, then verify checksums and finite nonzero vectors. Limits are 64 requested vectors, 2 MiB aggregate and 4096 retained cache rows. The wrapper has a five-second total deadline. Corrupt/missing derived cache emits an explicit warning and regenerates from the configured adapter; authoritative read errors are never handled by this cache. Cached vectors remain ranking hints and are revalidated against current authoritative scope/content/applicability by enhanced recall. Cache hits use the pinned profile and do not contact `/api/tags`; only fresh embedding generation checks current model tags. This is not ANN indexing.

Cache tests: `cargo test --test embedding_cache` (deterministic synthetic vectors, no model/network).
